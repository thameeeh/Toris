Working NPC Quest & Item Setup Checklist

A comprehensive checklist detailing all database variables, scene components, and dialogue flow scripts needed to set up an NPC that gives quests and rewards items.

To create a fully working Quest NPC setup: You must configure three completely separate layers. First, the data assets in the Dialogue/Item Databases; second, the physical GameObject Colliders & Interactables in your active scene; and third, the **Lua condition and script logic** inside your conversation node flowchart.

Phase 1 · The Data Prep (Databases & Assets)

Before placing an NPC in the scene, ensure the necessary quest logs, tracker variables, and item blueprints exist within your project databases.

Asset / Location What to Create & Fill Why It is Needed
Dialogue Database
(Variables Tab)		 Create a progress tracking variable (e.g. wolvesKilled) set as an integer with an initial value of 0. Lets the Dialogue System track counter progress globally.
Dialogue Database
(Quests Tab)		 Create the Quest (e.g. Kill3Wolves), set its state to unassigned, and add a Quest Entry 1 with display text: Wolves: [var.wolvesKilled]/3. Defines the quest UI, description text, and dynamic variable formatting.
Item Database SO
(Unity Asset Folder)		 Create and add your custom Item SOs (e.g., chipped_bone_charm, iron_ore) to your main ItemDatabaseSO registry. Ensures the custom C# inventory system recognizes and resolves the items you check or give.
Quest Fact Rule Set SO
(Unity Asset Folder)		 Add a rule mapping the Kill fact (Type/Tag: Wolf) to target quest Kill3Wolves and variable wolvesKilled. Tells the progress mapper how to link physical gameplay actions to database variable increments.

Phase 2 · The Physical NPC Setup (Unity Scene)

Ensure the NPC GameObject in the Unity Hierarchy is interactable and can launch the conversation state.

NPC GameObject Component Requirements

  • Collider2D (Set to Is Trigger): Required so the player's proximity sensor can detect the NPC when standing close by.
  • Dialogue NPC Proximity (Script) or Tag: Ensures that the player interactor recognizes this physical object as a valid dialogue trigger.
  • PixelCrushersConversationInteractable (Script):
    • Set Default Conversation to your starting conversation name (e.g. Guide_Intro).
    • Assign the NPC's GameObject to the Actor / Conversant fields so conversational cameras and triggers align correctly.

Phase 3 · The Conversation Flow (Dialogue Nodes)

Within your Dialogue Editor conversation tree, configure the conditions and scripts to transition between quest states and distribute rewards.

1. Offering and Activating the Quest

On your offer dialogue node, ensure the conditions specify the quest is currently unassigned, and set both the quest and its entry to active upon acceptance.

Offer Node Conditions:

Quest["Kill3Wolves"].State == "unassigned"

Offer Node Script:

SetQuestState("Kill3Wolves", "active");
SetQuestEntryState("Kill3Wolves", 1, "active");

2. Active Quest Status (In Progress)

Configure a reminder branch displayed while the player is pursuing the objectives.

Reminder Node Conditions:

Quest["Kill3Wolves"].State == "active"

Reminder Dialogue Text:

"You have defeated [var.wolvesKilled] / 3 wolves so far."

3. Handing In the Quest & Granting Rewards

Once the counter reaches 3, the progress mapper automatically marks the quest state as done (ReturnToNPC). Wire your completion node to check this and grant items.

Complete Node Conditions:

Quest["Kill3Wolves"].State == "done"

Complete Node Script:

TorisGiveItem("chipped_bone_charm", 1);
SetQuestState("Kill3Wolves", "success");

Important: Double check that the item name string inside TorisGiveItem("item_name") matches the asset name in your ItemDatabaseSO exactly!
