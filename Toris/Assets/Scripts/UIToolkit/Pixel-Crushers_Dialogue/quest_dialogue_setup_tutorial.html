Quest & Dialogue Unity Workflow

A complete, beginner-friendly walkthrough explaining exactly how to configure Dialogue Databases, set up dialogue paths, build NPC game objects, track gameplay achievements, and automate quest rewards in Unity using the Toris custom bridge scripts.

The Golden Architecture Rule:
The DialogueManager is a persistent singleton. It belongs in a global Boot/Persistent scene loaded first.
NEVER attach DialogueManager to individual NPC GameObjects in your levels!

Workflow Overview & Prerequisites

In Game Project Toris, the dialogue and quest system is highly decoupled. This keeps your game mechanics (combat, inventory, physics) clean. Instead of NPCs invoking hardcoded actions or writing UI code themselves, they communicate through thin custom bridges using the following flow:

Phase Action Target Assets / Components
1. Database Config Define the Quest, its entries, and matching variables inside Pixel Crushers. Dialogue Editor Tab Quests & Variables
2. Dialogue Trees Draft conversations, setting nodes to start/progress quests and check inventory state. Dialogue Editor Tab Conversations (using Lua)
3. NPC Triggers Equip physical Unity NPC GameObjects to react to proximity and trigger dialogues. PixelCrushersConversationInteractable & DialogueNpcProximity
4. Gameplay Tracking Fire C# gameplay events which update dialogue numbers automatically. PixelCrushersQuestFactReporter & QuestFactProgressRuleSetSO
5. Rewards & Saves Bind item/gold payouts and ensure progress is captured in player save files. PixelCrushersQuestRewardSetSO & PixelCrushersDialogueSaveBridge
⚠️

Important Note on Inspector Improvements

Thanks to recent codebase upgrades, you no longer have to type Quest Names or Conversation Titles manually in the Inspector! The fields in our custom components are now decorated with [QuestPopup] and [ConversationPopup], providing beautiful dropdown lists pulled straight from your database to eliminate typing errors.

1. Defining the Quest in the Dialogue Editor

Before your game can track a quest, you must declare it as a data structure inside the Dialogue Database.

1
Open the Dialogue Editor

In the Unity top menu, navigate to Window > Pixel Crushers > Dialogue System > Dialogue Editor. This opens the main database panel. Ensure your active project database is loaded (you will see its path in the database section).

2
Create a New Quest

Go to the Quests/Items tab, click the + icon on the left sidebar, and select New Quest. An empty quest configuration pane will appear.

🛠️ Crucial Quest Fields to Set:

  • Name: Set this to a unique ID with no special characters (e.g. GatherWood). This Name is the unique identifier! It must match the names used in your C# rules and ScriptableObjects exactly.
  • Display Name: The friendly title shown in the Quest Journal (e.g. "Firewood for the Forge").
  • Group: The category (e.g. "Smithy" or "Main Quests") for clean sorting.
  • State: Set this to unassigned. This is the initial state when the player has not yet taken the quest.
  • Description: A general summary of the task shown to the player.
3
Add Quest Entries (Objectives)

A quest often has sub-tasks or checkboxes. You track these using Quest Entries. Scroll down the quest pane to Entries, click + Add Entry:

  • Entry 1 Description: E.g., "Gather 5 Forest Wood ({#GatherWood_Count}/5)".
  • Note on syntax: The bracket token {#GatherWood_Count} tells the tracker UI to display the live value of the Lua database variable named GatherWood_Count automatically!
4
Declare variables in the Variables Tab

If your quest tracks quantities (like killing 5 monsters or gathering 5 items), go to the Variables tab in the editor:

  • Click + to add a variable.
  • Set its name to match your tracked count (e.g., GatherWood_Count).
  • Set its type to Number (integer) and initial value to 0.

2. Creating Dialogue Trees & Lua Scripting

Dialogue trees decide what an NPC says and when. They also query inventory items and transition quest states via built-in Lua hooks.

1
Create the Acceptance Conversation

Go to the Conversations tab, click +, and title it Blacksmith_OfferWoodQuest. Right-click nodes to draft the speech flow:

  1. Start with the NPC explaining the forge is out of firewood and asking for help.
  2. Create player response nodes (e.g. "I'll help you!" or "Maybe later.").
  3. Select the acceptance response node ("I'll help you!"). In its Inspector pane, find the Script field. Type this Lua statement to officially add the quest to the player's journal:
Quest["GatherWood"].State = "active"
2
Create the In-Progress Reminder Conversation

Create a conversation titled Blacksmith_ReminderWoodQuest.

  • NPC Dialogue: "Have you found that firewood yet? I need 5 logs of Forest Wood."
  • This line has no script or conditions — it is a simple reminder. We will bind this to play when the quest state is active.
3
Create the Turn-In Conversation (Checking & Handover)

Create a conversation titled Blacksmith_TurnInWoodQuest. This is where we safely check the player's inventory and complete the transaction.

  1. Create an NPC greeting node: "Ah! You're back! Did you find the wood?"
  2. Create a player choice node: "Yes, here are the 5 logs."
  3. Select this player node. In the Inspector, find the Conditions field and write:
TorisHasItem("ForestWood", 5)

This condition ensures this dialogue choice is only clickable or visible if the player actually has 5 pieces of ForestWood in their inventory bag.

  1. Create a child NPC response node to this choice: "Excellent! Let me get those out of your hands." Select this NPC node, and in its Script field, write:
TorisTakeItem("ForestWood", 5)
Quest["GatherWood"].State = "success"

This C# Lua bridge call strips the items from the player's inventory, and marks the quest as fully successful!

💡

Available Inventory & Gold Lua Calls

Our customized PixelCrushersInventoryBridge registers these exact Lua commands for your dialogue nodes. You can use them anywhere in Conditions or Scripts:

  • TorisHasItem("ItemName", count) · Returns true/false.
  • TorisGetItemCount("ItemName") · Returns current stock integer.
  • TorisGiveItem("ItemName", count) · Hands a physical item to the backpack.
  • TorisTakeItem("ItemName", count) · Strip items from the backpack.
  • TorisGetGold() · Returns current cash balance.
  • TorisGiveGold(amount) · Deposits coins directly to progression wallet.
  • TorisTakeGold(amount) · Charges the player's wallet.

3. Setting up NPC GameObjects in the Unity Scene

Now we link the database conversations to a physical NPC object standing in the Unity level, leveraging our trigger architecture.

1
Understand the GameObject Layout

Attach the components according to this decoupled design structure to ensure collision checks are isolated from dialogue launch routing:

⬤ NPC_Blacksmith (Root GameObject)
» Component: PixelCrushersConversationInteractable
┗ ⬤ ProximityTrigger (Child GameObject)
» Component: CircleCollider2D (Is Trigger = True)
» Component: DialogueNpcProximity
2
Set up the Root NPC GameObject

On your root NPC GameObject (e.g. NPC_Blacksmith):

  1. Attach the PixelCrushersConversationInteractable component.
  2. Set the Default Conversation dropdown to Blacksmith_Greeting (this conversation will play if the NPC has no active quests or jobs to discuss).
3
Set up the Proximity Trigger Child

Create a new empty child GameObject, name it ProximityTrigger:

  1. Add a CircleCollider2D (or BoxCollider2D), set its radius to the interaction range, and tick the Is Trigger checkbox.
  2. Add the DialogueNpcProximity component.
  3. In the inspector for DialogueNpcProximity:
    • Drag the player interactor scriptable asset into Player Interactor.
    • Drag the parent NPC_Blacksmith GameObject (which holds the conversation interactable) into the Interactable slot.
4
Configure Quest Conversation Routes (The Dropdowns!)

Go back to the root NPC's PixelCrushersConversationInteractable component. Locate the Quest Conversation Routes list. Add a new route:

  • Quest Name: Click the dropdown and select GatherWood. (No typing needed!)
  • Conversation When Unassigned: Select Blacksmith_OfferWoodQuest. (NPC offers help).
  • Conversation When Active: Select Blacksmith_ReminderWoodQuest. (NPC prompts progress).
  • Conversation When ReturnToNpc: Select Blacksmith_TurnInWoodQuest. (NPC completes the quest).
  • Conversation When Success: Select Blacksmith_CompleteTalkWoodQuest. (NPC says "Nice work!").

💡 How it works at runtime: When the player approaches the Blacksmith and presses E, the script evaluates the current state of the GatherWood quest and plays the matching conversation automatically. If the quest is finished, it falls forward to the success greeting!

4. Fact-Based Progress Tracking (Gameplay → Quest Progress)

How do we make gathering logs in the world update our quest counter? We use an Event Bus pattern to ensure gameplay scripts are 100% decoupled from quest dialogue databases.

1
Fire Facts in C# Gameplay Scripts

Whenever the player gathers a log, defeats a specific mob, or enters a dungeon region, write a single line of code in that trigger script to report the event: 

// Example: Inside your WoodHarvestable.cs script when wood is successfully chopped
QuestFact harvestFact = new QuestFact(
    QuestFactType.Collect, 
    "ForestWood", 
    1
);
PixelCrushersQuestFactReporter.Report(harvestFact);

This fires a global fact notification. The combat or harvesting system does not need to know what quest the player is currently tracking!

2
Create a Quest Fact Progress Rule Set SO

To capture this fact and map it to your quest variables, create a ScriptableObject mapping set:

  1. In the Unity Project window, right-click and choose Create > Quests > Quest Fact Progress Rule Set. Name the asset GatherWood_ProgressRule.
  2. Select the asset, and click + to add a rule entry:
  • Quest Name: Select GatherWood from the dropdown list.
  • Target ID: Enter ForestWood (must match the Target ID sent by the C# reporter exactly).
  • Fact Type: Select Collect.
  • Variable To Modify: Type GatherWood_Count (must match the number variable we declared in the database tab!).
  • Required Quantity: Set to 5.
  • Auto Complete And Update States: Tick this checkbox! When ticked, the mapper will automatically advance the overall quest state to ReturnToNPC the moment the player collects 5 logs, showing the "Talk to Blacksmith" notification automatically!
3
Attach the Quest Progress Mapper

Ensure your level scene contains the PixelCrushersQuestProgressMapper component (usually sitting on a manager GameObject):

  • Select the manager holding the component.
  • Drag your new GatherWood_ProgressRule asset into the Rule Sets array in the Inspector.
  • The mapper will now listen to facts and modify dialogue values automatically at runtime!

5. Automating Rewards, Abandonments & Save Persistence

When a quest finishes, players expect items, XP, and gold. Here is how to configure rewards visually and ensure data is safely persisted.

1
Configure Quest Rewards Visually

Rather than manually script items and gold in dialogue nodes, configure them visually:

  1. Right-click in Project view -> Create > Quests > Quest Reward Set. Name it ForgeRewards.
  2. Add a reward entry matching your quest:
    • Quest Name: Select GatherWood from the dropdown.
    • Gold Reward: 150
    • XP Reward: 300
    • Items: Drag static item database SO assets (e.g. BronzeAxeSO, HealthPotionSO) and set counts.
  3. Ensure the PixelCrushersQuestRewardAdapter component is present in your scene. Drag your ForgeRewards asset into its **Quest Reward Sets** list.
  4. The adapter will poll the database and automatically grant these items to the player's wallet and inventory bag the split-second the quest state changes to success!
2
Handling Quest Abandon Penalties

To penalize players for abandoning a quest:

  • Right-click -> Create > Quests > Quest Abandon Set.
  • Select your quest (e.g. GatherWood).
  • Add gold or item deduction settings to take effect when the player clicks the "Abandon" button in their Quest Journal UI!
3
Configuring Repeatable Daily Quests

If the forge quest is a repeatable "Daily Quest":

  • Right-click -> Create > Quests > Repeatable Quest Cooldown Set.
  • Select GatherWood.
  • Set **Cooldown Duration Seconds** to 86400 (24 hours).
  • When the quest completes, it locks. Once the cooldown timer expires, the script automatically resets the state to unassigned so the NPC offers it again!
4
Save & Load Persistence Setup

To ensure all active quest entries, variables, and completed statuses are kept when the player exits the game:

  • Locate your save game manager GameObject.
  • Ensure the PixelCrushersDialogueSaveBridge component is attached to it.
  • This script hooks into the Toris JSON save workflow. It captures all database metrics into a string blob and feeds it back on startup, completely managing your persistence with no extra code.

6. Gotchas & Pro Troubleshooting

Avoid these common pitfalls when setting up dialogues and quests in Unity:

❌ Gotcha 1: The Quest Journal Array Limitation

Unity's editor drawer system does not allow custom dropdown drawers inside standard `string[]` arrays.

⚠️ **Where this matters:** On your Quest Journal game objects, the _questsToMarkGrantable field is an array of strings. Because it is an array, the dropdown menu will NOT appear! You must manually type the exact Quest ID string inside array slots. Double-check your spelling!

⚠️ Gotcha 2: Common Lua Script Syntax Errors

Lua is case-sensitive and has strict syntax. Common mistakes inside Dialogue Editor nodes:

  • Capitalization: Write Quest["MyQuest"].State with a capital **Q**. Writing quest["MyQuest"] with a lowercase "q" will cause a Lua evaluation crash!
  • Operators: In the Conditions field, always use double-equals == for checks (e.g. Quest["GatherWood"].State == "active"). In the Script field, always use single-equals = for variable assignment (e.g. Quest["GatherWood"].State = "success").

💡 Gotcha 3: Permanent Player Input Freezes

When dialogue starts, the PixelCrushersDialogueCommandBridge automatically triggers an input lock event to freeze the player's movement and controls.

**The Pitfall:** If a conversation ends abruptly due to an editor error or missing dialogue tree exit path, the player will remain frozen! If this happens, ensure your conversation nodes always lead to a valid terminal end node, and that the command bridge is listening to the Dialogue Manager's conversationEnded callbacks.
