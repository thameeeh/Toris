Integrating Inventory & Dialogue

Learn the core architecture of the Toris Inventory system and how to integrate items, currencies, and quest progress with the Pixel Crushers Dialogue System.

1. Architecture & Key Components

The inventory and item system is built around Transactional Safety and a Decoupled Architecture. Decoupling ensures that dialogue scripts don't have hard references to physical player controllers, which preserves stability.

System Data-Flow Pipeline
GameSessionSO
GLOBAL ENTRY HUB
Facilitates runtime access to backpack & wallet
InventoryManager
TRANSACTION CONTROLLER
Manages LiveSlots & safe item mutation
ItemDatabaseSO
ID REGISTRY
Resolves string IDs into template assets
PlayerProgression
WALLET & XP
Stores experience and gold quantities
GameSessionSO Facade
OutlandHaven.UIToolkit

Acts as the central facade mapping active controllers. When components initialize, they bind themselves here (e.g., PlayerInventory). 

var session = GameSessionSO.LoadDefault();
var backpack = session.PlayerInventory;
InventoryManager Controller
OutlandHaven.Inventory

Directs the slots. Exposes transactional check methods like CanAddItem and RemoveItem to ensure slot additions succeed fully or fail gracefully.

ItemDatabaseSO Registry
OutlandHaven.Inventory

Matches string IDs coming from dialogue configurations to actual static InventoryItemSO templates with O(1) efficiency.

ItemInstance Stack
OutlandHaven.Inventory

An active instance of an item in a slot. Carries volatile stack values (durability, counts, state updates) and is deep-cloned upon transaction entry.

2. Dialogue & Quest System Bridge

The custom C# component PixelCrushersInventoryBridge binds our inventory and wallet APIs directly into the Pixel Crushers Dialogue System's Lua virtual machine. You can use these methods directly in node Conditions or User Scripts.

Lua Signature Operation Type Description Example Usage
TorisHasItem(itemID, quantity) Boolean Check Returns true if player's backpack holds the required quantity. TorisHasItem("Wood", 5)
TorisGetItemCount(itemID) Number Check Returns the total count of the item inside the backpack. TorisGetItemCount("Iron") > 2
TorisGiveItem(itemID, quantity) Boolean Action Gives items to the player. Returns true if successful. TorisGiveItem("Potion", 1)
TorisTakeItem(itemID, quantity) Boolean Action Removes items from backpack. Returns true if successful. TorisTakeItem("IronOre", 3)
TorisGetGold() Number Check Returns the player's wallet balance. TorisGetGold() >= 100
TorisGiveGold(amount) Boolean Action Adds gold to the player's wallet. TorisGiveGold(150)
TorisTakeGold(amount) Boolean Action Deducts gold. Returns false if the player is too broke. TorisTakeGold(50)

3. Setup & Integration Guide

Integrating your inventory with quests involves two straightforward steps.

Step 1: Add the Bridge Component

  • In your active scene, select the persistent Dialogue Manager GameObject.
  • Add the PixelCrushersInventoryBridge component.
  • Drag the master ItemDatabaseSO asset from your project pane into the Item Database field.
💡

Pro-Tip

If you leave the database field empty in the Inspector, the script will automatically fallback to load an asset named "Data/ItemDatabase" inside a standard Resources folder.

Step 2: Apply in Conversations

Scenario A: Blocking dialogue based on items (Conditions)

If an NPC should only show a choice if the player has 5 pieces of wood:

-- Place this inside the Conditions field of the dialogue line
TorisHasItem("Wood", 5)

Scenario B: Exchanging items mid-conversation (Scripts)

To take the 5 wood and give the player 100 gold and a health potion upon selection:

-- Place this inside the User Script field of the dialogue line
TorisTakeItem("Wood", 5);
TorisGiveGold(100);
TorisGiveItem("HealingPotion", 1);

4. Technical Integration Best Practices

Database Maintenance

Whenever you introduce a new InventoryItemSO asset to the project, open your master ItemDatabaseSO and click the Auto-Populate Database button in the inspector. This rebuilds the internal dictionary and ensures the dialogue system recognizes the new item's string ID.

Updating Quest Log HUD via Facts

If you need the dialogue system to update the active quest log text with collection counts, invoke the companion script reporter TorisReportFact in the dialogue scripts: 

-- Updates the quest collector HUD with the transaction progress
TorisReportFact("Collect", "Wood", "QuestItem", 5, "WoodcutterQuest")
